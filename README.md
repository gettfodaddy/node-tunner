# node-tuning

Один Bash-скрипт, который проверяет Linux-сервер, настраивает его под сетевую ноду и при необходимости возвращает всё как было.

```
1  Проверка сервера   → вердикт и рекомендации, ничего не меняется
2  Тюнинг сервера     → бэкап → применение → проверка
3  Откат              → возврат к состоянию до тюнинга
```

## Что делает

| Область | Что настраивается | Зачем |
|---|---|---|
| **Сеть и ядро** | BBR + очередь `fq`, буферы TCP/UDP, `conntrack`, очереди приёма, диапазон портов, MTU-probing | Выше скорость на дальних клиентах и каналах с потерями, меньше потерь пакетов на пиках |
| **Swap** | Нет — создаёт, мало — увеличивает | Страховка от OOM-killer. Размер подбирается по объёму RAM |
| **Лимиты Docker** | `LimitNOFILE` и `LimitNPROC` до 1048576 | Каждое соединение — открытый файл. На дефолтной тысяче нода отказывает клиентам, оставаясь «живой» |
| **Диск** | Лимит логов контейнеров, лимит журнала systemd (200 МБ), очистка `btmp` | Нода не отваливается из-за забитого диска |

Значения буферов, таблицы соединений и размер swap зависят от объёма RAM. Всё, что уже лучше цели, скрипт не понижает.

## Быстрый старт

```bash
sudo bash node-tuning.sh            # интерактивное меню
sudo bash node-tuning.sh about      # краткая справка: что проверяет и делает скрипт
sudo bash node-tuning.sh check      # только проверка
sudo bash node-tuning.sh tune -y    # тюнинг без вопросов
sudo bash node-tuning.sh rollback   # откат
```

Скрипт замеряет скорость скачивания до и после тюнинга и показывает разницу.

## Как это работает

1. **Проверка.** Скрипт сверяет текущие значения с целевыми. Для каждого расхождения он показывает, за что отвечает параметр, затем выдаёт вердикт и список рекомендаций.
2. **Тюнинг.** Скрипт показывает план и просит подтверждение. Затем сохраняет снимок системы, применяет swap, `sysctl`, очередь, лимиты Docker и настройки диска. После этого он сверяет, что значения встали, и замеряет скорость.
3. **Откат.** Скрипт восстанавливает конфиги, живые значения ядра, swap, очередь пакетов и настройки Docker и журнала из выбранного снимка.

Docker перезапускается **один раз** за весь тюнинг. Клиенты отвалятся примерно на 10 секунд, а при пересоздании контейнера — ещё раз. Запускайте в тихое окно.

## Безопасность

- Перед любым изменением создаётся снимок в `/var/backups/node-tuning/<дата>/`.
- Конфиги Docker не затираются: существующий `daemon.json` аккуратно дополняется.
- Параметры, которых нет в ядре, пропускаются без ошибок.
- На контейнерной виртуализации (OpenVZ, LXC и т. п.) тюнинг блокируется: там нельзя менять ядро.
- **Не откатываются:** очистка журнала, обнуление `btmp` и пересоздание контейнера. Скрипт предупреждает об этом заранее.

## Требования

Linux с systemd, root-доступ, `curl`, `iproute2`. Для настроек Docker нужен установленный Docker. Имя контейнера ноды задаётся переменной `NODE_CONTAINER`. Переменная `NO_COLOR=1` отключает цвета и анимацию.
